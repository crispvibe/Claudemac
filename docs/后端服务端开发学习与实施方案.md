### 后台 Vue 调用链

后台请求统一走：

```text
src/utils/request.js
  -> axios
  -> baseURL = import.meta.env.VITE_BASE_API
  -> 响应要求 {code,data,msg}
  -> code=0 视为成功
  -> 401 清理登录态并跳回 Login
```

后台路由不是前端静态写死，而是数据库动态菜单：

```text
src/router/index.js
  -> 只注册 Login / NotFound
src/pinia/modules/router.js
  -> fetchNavigationRoutes()
  -> 后端返回 navigation_entries
  -> asyncRouterHandle 动态挂载页面
```

开发后台页面时需要同时处理：

- `后端/web/src/api/*.js`
- `后端/web/src/view/console/**`
- `后端/web/src/componentRegistry.generated.js` 或构建插件生成的组件标识
- 数据库 `navigation_entries`
- 数据库 `role_navigation_entries`
- 数据库 `api_catalog`
- 数据库 `casbin_rule`

### 后台组件标识机制

后台菜单表不直接稳定使用 Vue 文件路径，而是使用 `cmp_` 开头的组件标识。

关键文件：

```text
后端/web/vitePlugin/componentName/index.js
后端/web/src/componentRegistry.generated.js
后端/web/src/utils/componentRegistry.js
后端/web/src/utils/asyncRouter.js
后端/server/model/admin/component_identifier_manifest.json
后端/server/model/admin/component_identifier.go
```

机制：

- Vite 插件扫描 `后端/web/src/view/**/*.vue`。
- 插件读取 `后端/server/model/admin/component_identifier_manifest.json`。
- manifest 里的 `relativePath -> componentId` 必须覆盖所有 Vue 页面。
- 如果新增 Vue 页面但不更新 manifest，插件会报 `component identifier manifest mismatch`。
- 后端菜单 `navigation_entries.component` 要写 manifest 中的 `componentId`。
- 前端动态路由通过 `componentId` 找到真实 Vue loader。

所以新增后台页面时，不能只加 `.vue` 文件；还必须补 manifest 和菜单 seed。

后续远程模块应按现有风格放在：

```text
api/v1/biz/remote_*.go
router/biz/remote_*.go
service/biz/remote_*.go
model/biz/remote_*.go
model/biz/request/remote_*.go
model/biz/response/remote_*.go
```

## 关键框架约束

### 1. 不建议复用后台账号体系做 App 用户

现有 `accounts` 是后台账号：

- 有 `username`
- 有 `nick_name`
- 有 `primary_role_id`
- 绑定角色、菜单、Casbin
- JWT claims 带 `RoleID`

远程 App 需求是：

- 只用手机号注册。
- 不需要昵称。
- 不需要后台角色。
- 不需要菜单权限。

所以建议新增独立表 `remote_users`，不要把普通 iOS/Mac 用户混入后台 `accounts`。

### 2. 不建议复用后台 JWT 中间件

现有私有路由默认：

```text
PrivateGroup.Use(JWTAuth()).Use(CasbinHandler())
```

这会强绑定后台账号和 Casbin 权限。远程 App API 建议单独做：

```text
/remote/auth/register
/remote/auth/login
/remote/legal-documents
```

公共可访问。

登录后接口使用独立 `RemoteJWTAuth`：

```text
/remote/devices
/remote/device-codes/resolve
/remote/connections
/remote/legal-consents
```

不走后台 Casbin。

### 3. 生产表结构不要依赖 AutoMigrate

配置里当前是：

```yaml
system:
  disable-auto-migrate: true
```

`RegisterTables()` 会直接跳过 AutoMigrate。后续应准备 MySQL 5.7 兼容 SQL 迁移脚本，再用 MCP 或部署脚本执行。

补充说明：

- `acode` 当前为空库，只代表还没有初始化。
- 如果后续开启 AutoMigrate 或执行迁移脚本，框架会创建后台表。
- 如果 `system.env = local` 且菜单表为空，`bootstrapLocalBaselineData()` 会写入基础后台数据。
- 基础数据包括：admin 账号、角色、菜单、角色菜单绑定、账号角色绑定、数据权限、忽略鉴权接口。
- `service/admin/bootstrap.go` 还会根据运行路由补齐 API catalog 和管理员 Casbin 权限。

因此数据库不能按“一直 0 表、0 数据”理解。正确口径是：当前未初始化；一旦执行框架初始化或迁移，会入库后台基础结构和数据。

### 当前复制框架的初始化缺口

`README.md` 提到：

```text
server/local-init/bootstrap.sql
```

但当前复制进项目的 `后端/server` 内未找到该 SQL 文件。因此不能假设已有完整 SQL 初始化脚本。后续必须二选一：

1. 补齐 MySQL 5.7 初始化 SQL。
2. 或临时开启 `disable-auto-migrate: false` 让框架 AutoMigrate 后，再固化 SQL。

生产建议最终仍使用 SQL 迁移，不依赖 AutoMigrate。

## 后台管理功能影响面

如果第一阶段只做 App API，可以先不做后台页面。

但以下能力最终应该进入 Vue 后台：

- 远程用户列表。
- 设备列表。
- 连接记录。
- 设备码解析/失败日志。
- 隐私政策/用户协议编辑发布。
- 用户协议同意记录。
- 订阅/权益状态。

后台管理页落地时必须同步：

1. Go admin/biz API。
2. Vue `src/api`。
3. Vue `src/view/console` 页面。
4. 菜单数据 `navigation_entries`。
5. 角色菜单绑定 `role_navigation_entries`。
6. API 名录 `api_catalog`。
7. Casbin 权限 `casbin_rule`。

否则页面可能存在但菜单不显示，或接口存在但后台无权限。

MySQL 5.7 注意点：

- 不使用 MySQL 8 专属语法。
- JSON 字段慎用；核心查询字段不要放 JSON。
- 字符集使用 `utf8mb4`。
- 字符索引长度控制在 191 内。
- 时间字段统一 `datetime(3)` 或 `datetime`，按框架习惯选一种。

## 连接规则

同账号：

```text
iOS 登录账号
  -> 获取自己的桌面设备
  -> 选择设备
  -> 后端校验同账号、在线、远程开关、权益
  -> 直接 accepted
  -> 不需要电脑确认
```

跨账号：

```text
桌面端显示固定设备码
  -> iOS 输入设备码
  -> 后端解析目标设备
  -> 如果目标设备策略是 always_ask，创建 pending
  -> 桌面确认后 accepted
  -> 如果目标设备策略是 allow_anyone，直接 accepted
```

## 风险与待确认

1. 新 MCP 已配置，但当前会话还不能直接调用 `mcp__mysql_acode__`，需要重启 Codex 后验真实数据库。
2. 远程用户表要独立于后台账号表，否则会引入角色和 Casbin 干扰。
3. 远程 App API 需要独立认证中间件，否则登录后会被后台 Casbin 拦截。
4. 当前框架默认关闭 AutoMigrate，后续必须写 SQL 迁移。
5. Redis 当前默认关闭，后续在线状态、限流、连接状态需要 Redis；第一版可以先用 DB 状态，信令阶段再启 Redis。
6. 设备码是固定码，必须限流、hash 存储、可重置。
7. 后端第一阶段不应代理聊天正文，不保存 Claude 输出和项目文件。
