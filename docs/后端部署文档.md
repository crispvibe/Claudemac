## 部署模式

本项目后端部署固定采用纯二进制方式：

```text
本机 macOS 交叉编译 Linux amd64 二进制
  -> scp 上传到服务器 releases 目录
  -> install 切换到 backend/bin/acode-api
  -> systemd 重启 acode-api.service
  -> Nginx 反代 127.0.0.1:8868
```

明确不使用：

- Docker
- Docker Compose
- 服务器在线 `go build`
- 上传完整源码后在服务器编译

## systemd 服务

服务名建议：

```text
acode-api.service
```

创建服务：

```bash
ssh -i /Users/oreo/Desktop/ssh-root-8.156.64.76-ed25519 -p 22 root@8.156.64.76 'cat > /etc/systemd/system/acode-api.service <<EOF
[Unit]
Description=Codevoke Backend API
After=network.target mysqld.service redis.service
Wants=network-online.target

[Service]
Type=simple
User=www
Group=www
WorkingDirectory=/www/wwwroot/acode.anna.vin/backend
Environment=GIN_MODE=release
ExecStart=/www/wwwroot/acode.anna.vin/backend/bin/acode-api -c /www/wwwroot/acode.anna.vin/backend/config.yaml
Restart=always
RestartSec=5
LimitNOFILE=65535
StandardOutput=append:/www/wwwroot/acode.anna.vin/backend/log/stdout.log
StandardError=append:/www/wwwroot/acode.anna.vin/backend/log/stderr.log

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable acode-api.service
'
```

## Nginx 反向代理

宝塔主站点配置：

```text
/www/server/panel/vhost/nginx/acode.anna.vin.conf
```

建议不要直接在主配置中大段手改，优先在扩展目录新增独立文件：

```text
/www/server/panel/vhost/nginx/extension/acode.anna.vin/acode-api-proxy.conf
```

推荐内容：

```nginx
location = /health {
    proxy_pass http://127.0.0.1:8868;
    include proxy.conf;
}

location = /admin {
    return 302 https://acode.anna.vin/#/admin/login;
}

location = /admin/ {
    return 302 https://acode.anna.vin/#/admin/login;
}

location /api/ {
    proxy_pass http://127.0.0.1:8868;
    include proxy.conf;
}

location /remote/ {
    proxy_pass http://127.0.0.1:8868;
    include proxy.conf;
}

location /remote/signaling/ws {
    proxy_pass http://127.0.0.1:8868;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

说明：

- `/health` 用于健康检查。
- `/admin` 和 `/admin/` 统一跳转到后台登录页。
- `/api/` 预留普通后端 API。
- `/remote/` 预留账号、设备、授权、订阅等远程能力。
- `/remote/signaling/ws` 预留 WebSocket signaling，必须单独配置 Upgrade。
- 如果后端接口最终挂在随机 `router-prefix` 下，需要同步调整 Nginx 路径。

检查并重载 Nginx：

```bash
ssh -i /Users/oreo/Desktop/ssh-root-8.156.64.76-ed25519 -p 22 root@8.156.64.76 '
/www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
/www/server/nginx/sbin/nginx -s reload -c /www/server/nginx/conf/nginx.conf
'
```

## CDN/HTTPS 注意事项

`acode.anna.vin` 已套 EAS 类似 CDN，公网已具备 HTTPS。部署后需要额外确认：

- CDN 是否回源到 `8.156.64.76:80`。
- CDN 是否允许 `/api/`、`/remote/` 动态接口不缓存。
- CDN 是否支持 WebSocket，并对 `/remote/signaling/ws` 开启 WebSocket 透传。
- CDN 是否保留 `Authorization` 请求头。
- CDN 是否保留 `Upgrade` / `Connection` 请求头。
- 如果 CDN 到源站使用 HTTP，而用户到 CDN 使用 HTTPS，后端通过 `X-Forwarded-Proto` 判断真实协议。

## 后续开发前置事项

在真正部署远程后端 API 前，还需要完成：

1. 确认生产 MySQL 数据库名、账号和权限。
2. 确认 Redis 是否作为远程在线状态、远程码 TTL、signaling fanout 使用。
3. 确认 `router-prefix` 是否为空，还是使用随机后台入口。
4. 确认 `/api/`、`/remote/`、`/remote/signaling/ws` 的最终路由规划。
5. 确认 CDN 对动态接口和 WebSocket 的透传规则。
6. 准备数据库迁移 SQL，生产不要依赖 GORM AutoMigrate。
7. 准备部署脚本，把构建、上传、切换、重启、验证、回滚固定下来。
